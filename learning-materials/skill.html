Skill（AI 技能）核心要点

理解给 AI 智能体的"可复用指令包"——让通用模型在特定任务上像专家

一句话定义：Skill（技能）是给 AI 智能体的"可复用指令包"——把某个领域的最佳实践打包成结构化文件，让 AI 遇到相关任务时按专家方法执行。它不是一次性的提示词（prompt 用完就丢），也不是模型微调（不改模型权重，外置的知识包），也不是工具调用（工具是 Agent 用来"做事"的函数，Skill 是用来"教方法"的指令）。

核心机制（6 个组件）

1. 触发条件 (Triggers)
定义什么时候该用这个 Skill。可以由 AI 自动判断（根据问题关键词/场景匹配），也可以由用户手动调用（明确说"用 XX 技能"或 /skill-name）。
2. 按需加载 (On-demand Loading)
Skill 不被预先塞进主上下文，而是在需要时由 AI 加载。避免污染主上下文、节省 token，又能按需获得专业知识。
3. 内容结构 (Structure)
通常一个 Skill = 一个文件夹，里面是 SKILL.md：YAML 头（元数据：name / description / when_to_use）+ 正文（详细步骤、最佳实践、注意事项）。复杂 Skill 可附带 scripts/、references/ 等。
4. 层级与作用域 (Scope)
用户级：放在 ~/.skills/，个人所有项目通用；
项目级：放在仓库内 .workbuddy/skills/（或类似路径），只服务于当前项目/团队，便于沉淀团队规范。本仓库采用的就是项目级 Skill。
5. 可组合 (Composable)
多个 Skill 可按任务组合使用。比如"写论文"任务可能同时加载"学术写作规范"+"引用格式"+"降重"等多个 Skill。
6. 可版本化 (Versioned)
作为文件存放在仓库里，可以用 Git 跟踪变更、code review、回滚。这是 Skill 优于一次性提示词的关键。

一个具体应用场景

场景：团队"提交代码" Skill（项目级）
团队希望所有 commit 都符合规范，并自动跑测试。
  1. 在仓库 .workbuddy/skills/commit-helper/SKILL.md 中定义：commit message 用 Conventional Commits 格式；提交前必须跑 lint + 单测；CHANGELOG 必须同步更新
  2. 开发者对 AI 说"提交代码" → AI 加载该 Skill
  3. AI 按 Skill 步骤：检查变更 → 生成合规 commit msg → 跑 lint → 跑 test → 检查 CHANGELOG → 提交
  4. 新成员入职后，无需口头培训，只要会用 AI + 这个 Skill，提交就自动规范
  5. 规范更新时，改 SKILL.md 一个文件，所有人下次提交自动用新规范

容易混淆的问题与边界

坑 1：把 Skill 当提示词。提示词是一次性输入，用完就丢；Skill 是结构化、可复用、可版本化的资产，应放在仓库里随项目迭代。
坑 2：把 Skill 当微调（fine-tuning）。微调改变模型权重，成本高、不可逆；Skill 只是外置的指令，不改模型，随时可改可删。
坑 3：把 Skill 当工具（tool）。工具是 Agent 用来"做事"的函数（搜网页、跑代码）；Skill 是用来"教方法"的指令。两者可以配合：Skill 里指挥 Agent 调哪些工具。
边界：Skill 适合重复、有标准流程、可沉淀的任务；不适合一次性探索、低频操作、纯创意发散。判断标准："这件事我或团队要做 ≥ 3 次且流程固定"，就值得做 Skill。

自测题（5 道）

1. Skill 和一次性提示词（prompt）最本质的区别是什么？
看答案
提示词是单次输入、用完即丢；Skill 是结构化、可复用、可版本化（Git 管理）、可共享的资产。Skill 是把"领域专家方法"沉淀下来，提示词是临时对话。
2. Skill 和模型微调（fine-tuning）有什么区别？
看答案
微调改变模型权重，成本高、需要训练数据、不可逆；Skill 不改模型权重，只是外置的指令文件，可随时修改、删除、共享，成本极低。Skill 是"轻量级的能力外挂"。
3. Skill 和 Agent 调用的"工具（tool）"有什么区别？
看答案
工具是"做事"的函数（搜网页、跑代码、读写文件，由系统执行）；Skill 是"教方法"的指令（告诉 AI 该怎么想、按什么流程做、什么时候调哪些工具）。Skill 指导 Agent 调工具。
4. 用户级 Skill 和项目级 Skill 的区别？本仓库用的是哪种？
看答案
用户级放 ~/.skills/，个人所有项目通用；项目级放仓库内 .workbuddy/skills/，只服务于当前项目/团队，便于沉淀团队规范。本仓库 concept-learning-generator 是项目级 Skill。
5. 什么时候值得造一个 Skill？
看答案
判断标准：这件事要做 ≥ 3 次、流程固定、有最佳实践可总结。满足这三条，做成 Skill 就能省下大量重复指导 AI 的时间，且规范可沉淀、可传承。一次性探索或纯创意任务不值得做成 Skill。
