Agent 核心要点

理解"会做事的大模型应用"：感知 → 思考 → 行动 → 观察 → 循环

一句话定义：Agent 是一个能感知环境 → 推理规划 → 调用工具行动 → 观察结果 → 循环迭代的大模型应用。它不是一个只会聊天的 chatbot（chatbot 只回答不行动），也不是通用人工智能 AGI（Agent 是一种架构模式，不等同于"超级智能"）。

核心机制（6 个组件）

1. 感知 (Perceive)
接收用户输入和环境反馈（工具返回结果、错误信息）。这是 Agent 与世界交互的入口。
2. 推理 / 规划 (Reason / Plan)
用 LLM 把大目标拆成子任务，决定下一步做什么（搜什么、调哪个工具、读哪段文档）。这一步是 Agent 的"大脑"。
3. 行动 (Act)
调用工具执行具体动作：网页搜索、读写文件、跑代码、查数据库、调 API。工具能力决定 Agent 的"手脚"边界。
4. 观察 (Observe)
拿到工具返回的结果或错误，纳入下一轮推理。观察能力决定 Agent 能否从错误中恢复。
5. 循环 / 迭代 (Loop)
把"观察 → 推理 → 行动"循环起来，直到目标完成或达到终止条件（最大步数、置信度阈值）。
6. 记忆 (Memory)
短期靠上下文窗口，长期靠外部存储（向量数据库、文件系统）。没有记忆的 Agent 每次都从零开始。

一个具体应用场景

场景：研究助手 Agent —— 调研"RAG 技术的最新进展"
用户对 Agent 说："帮我调研 2024–2025 年 RAG 技术的主要进展，并写一份对比报告。"
  1. Agent 拆解：搜最新综述 → 读代表性论文 → 提取关键方法 → 对比优缺点 → 写报告
  2. 调用工具：web_search（搜 arXiv 综述）→ pdf_reader（读论文）→ code_interpreter（画对比表）
  3. 每一步用 LLM 推理决定下一步该读哪篇/搜什么
  4. 观察到论文质量参差时，Agent 会换关键词重搜，而不是硬读
  5. 最终输出结构化对比报告，附引用

容易混淆的问题与边界

坑 1：把 Agent 当万能。简单问题（"把这段话翻译成英文"）用 Agent 反而更慢更贵。Agent 适合多步、需要外部信息、可验证的任务。
坑 2：忽视循环终止条件。Agent 可能死循环、跑偏或无限调工具。必须明确"什么时候算完成"（最大步数、置信度、超时）。
坑 3：把 Agent 等同 AGI。Agent 是一种架构模式（LLM + 工具 + 循环），不等于"超级智能"。它没有自主意识，目标仍由人给定。
边界：当前主流 Agent 在"明确目标 + 工具齐全 + 可验证"的任务上表现好；开放式创意、价值判断、长程规划仍弱。

自测题（5 道）

1. Agent 和普通 chatbot 最本质的区别是什么？
看答案
Chatbot 只被动回答（输出文字）；Agent 能主动调用工具、采取行动、观察结果并迭代。本质区别在于"是否改变外部环境"。
2. Agent 的核心循环是哪几步？
看答案
感知 → 推理/规划 → 行动（调工具）→ 观察 → 循环，直到目标完成或达到终止条件。
3. 什么时候不该用 Agent？
看答案
任务单步、确定、不需要外部信息时（翻译、改写、简单问答），用 Agent 反而更慢更贵、可能出错。Agent 的价值来自多步+工具+迭代。
4. ReAct 论文里 "Re" 和 "Act" 分别指什么？
看答案
Re = Reasoning（推理/思考下一步）；Act = Acting（调工具执行动作）。ReAct 把两者交替进行，让 LLM 在推理中决定何时调工具。
5. 给出 Agent 失败的一个常见原因（设计层面）。
看答案
常见原因：没有明确的终止条件导致死循环；工具描述不清楚导致 Agent 选错工具；目标太模糊导致 Agent 跑偏；上下文窗口溢出导致后期推理混乱。
