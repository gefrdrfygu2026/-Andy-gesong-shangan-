重点关系 1：上下文如何影响 Agent 的工作？

上下文是 Agent 的"工作台面"，决定了 Agent 在每一步推理中"能看到什么、记住什么、被什么约束"。它对 Agent 的影响体现在四个层面：

① 决定 Agent 的"视野"：上下文窗口外的任何信息，Agent 都"看不见"。所以检索（RAG）、对话历史、工具结果必须主动塞进上下文，否则 Agent 就像失忆。

② 决定 Agent 的"行为约束"：系统提示、角色定义、安全规则都在上下文里。改一句系统提示，Agent 的整个行为模式就可能变化。

③ 决定 Agent 的"成本与速度"：上下文越长，费用越高、延迟越大。这直接影响 Agent 是否能在生产环境大规模使用。

④ 决定 Agent 的"推理质量"："Lost in the Middle" 现象说明，关键信息放对位置（开头或结尾）比"塞很多信息"更重要。上下文设计本身就是一种工程。

重点关系 2：Skill 如何沉淀可复用的任务知识？

Skill 是把"散落在各次对话里的经验"外置化、结构化、可复用化的机制。它通过三条路径沉淀知识：

① 从"反复说的话"到"一次配置"：以前每次让 AI 写 commit，都要重复"用 Conventional Commits 格式、先跑 lint、跑测试"——现在写进一个 Skill，下次一句话触发。

② 从"个人经验"到"团队资产"：项目级 Skill 放在仓库里，随代码一起版本化、code review、新成员 onboarding。一个人的最佳实践变成整个团队的。

③ 从"上下文管理"到"上下文方法论"：Skill 里可以沉淀"该怎么组织上下文"（例如"关键约束放系统提示"、"长文档用 RAG 检索而不是全塞"）。Skill 不仅教做事，还教"怎么用好上下文"——这就是图中关系 ④ 的含义。

三句话总结

Agent 是一位会做事的助理；
上下文 是助理眼前的桌面和桌上的资料；
Skill 是公司给助理配的岗位手册——把"经验"沉淀成"方法"，让这位助理在每个新任务上都能立刻按专家方式工作。
