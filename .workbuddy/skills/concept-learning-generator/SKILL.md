# 概念学习资料生成 Skill

## 适用场景

当你需要**系统学习一个新概念**（技术术语、学科概念、方法论），并希望产出一份同时满足以下条件的资料时，使用本 Skill：

- 结构化、可视化、可分享（单一 HTML 文件）
- 包含**个人理解、机制、场景、边界、来源**
- 可以放进个人学习仓库归档、长期复用

**不适用**：
- 只需要一句话定义（直接问答即可）
- 纯操作/步骤类教程（用教程生成器更合适）
- 需要实时数据/行情的查询类需求

## 输入信息

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| 概念名称 | ✅ 必填 | 要学习的概念，如 "Agent"、"注意力机制" |
| 学习深度 | 可选 | `beginner` / `intermediate` / `advanced`，默认 `intermediate` |
| 侧重点 | 可选 | 希望重点理解的方面，如 "工作机制"、"应用案例"、"历史发展" |

## 生成步骤（6 步）

1. **澄清概念边界**：用一句话同时说清楚**是什么**和**不是什么**（避免与相似概念混淆）
2. **拆解核心机制**：用 2–4 个子部分解释它**怎么工作 / 由什么组成**
3. **给一个具体应用场景**：选一个**真实、可描述、有细节**的场景（有人物/系统/数据/结果）
4. **梳理容易混淆的问题与边界**：列出 2–4 个**新手常踩的坑**或**使用边界**
5. **列出可核查的资料来源**：至少 3 个，**必须是真实可访问的链接**
6. **设计 3–5 道自测题**：每题配答案，检验是否真正理解

## 输出结构（HTML 固定区块，顺序不变）

```
[徽章]    1 分钟学完 · <概念名>
[主标题]  <概念名> 核心要点
[定义框]  一句话定义（含"不是什么"）
[核心机制]  2-4 个子卡片
[应用场景]  1 个具体场景（含细节）
[边界与坑]  2-4 条
[资料来源]  3+ 个可核查链接
[自测题]   3-5 道（原生 <details> 交互）
[页脚]    生成方式 + 自检声明
```

设计要求：
- 浅色主题、清晰排版、1–2 分钟可读完
- **纯 HTML + CSS 自包含**，可离线打开
- 可用原生 `<details>` 做"看答案"交互
- **不依赖任何外部 CDN / 字体 / 脚本**

## 资料来源要求（硬性）

- ✅ **必须可核查**：每个来源链接点击能打开真实页面
- ✅ **优先级**：① 原始论文/arXiv ② 官方文档 ③ 标准/规范 ④ 权威作者博客
- ❌ **禁止**：编造论文标题/作者/年份、编造不存在的文档链接、用"网上说"代替具体出处
- ⚠️ 找不到 3 个可信来源时，**应减少数量并注明原因**，而不是编造

## 自检要求（生成后必须逐条核对）

- [ ] 一句话定义是否**同时**说了"是什么"和"不是什么"
- [ ] 核心机制是否解释了"怎么工作"，不是只罗列名词
- [ ] 应用场景是否**具体**（有人物/系统/数据/结果），不是泛泛而谈
- [ ] 边界部分是否真的标出了**容易混淆**的点
- [ ] 所有资料链接**实际验证过**可访问
- [ ] 自测题能真正检验理解（不是"XX 是 Y 吗？"式废话题）
- [ ] HTML **自包含**（能离线打开，不依赖外网）
- [ ] 内容避免整段照搬——用第一人称"我"的视角重述
- [ ] 若仓库内已有相关学习资料，与之保持术语一致

## 复用方式

本 Skill 是**通用**的，可为**任何概念**生成学习资料，不限于 Agent / 上下文 / Skill。

存放路径（项目级 Skill）：
```
<仓库根>/
└── .workbuddy/
    └── skills/
        └── concept-learning-generator/
            └── SKILL.md   ← 本文件
```

调用方式（在 WorkBuddy 中打开本仓库后）：
- **自动触发**：对 AI 说"用 concept-learning-generator 学习 XX 概念"
- **手动触发**：明确说"请按 `.workbuddy/skills/concept-learning-generator` 这个 Skill 的流程，生成 XX 的学习资料"
- 也可直接复制本 SKILL.md 的"生成步骤"+"输出结构"段落，发给任意 LLM 复用
